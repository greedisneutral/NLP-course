# Инструкция по выполнению и отправке задания

В рамках домашней работы вам необходимо дописать код в ноутбуке и реализовать функции в `solution.py` (`solution_empty.py` - исходник), обучить 2 модели FastText. Проверка задания происходит в системе Яндекс Контекст, поэтому вам необходимо четко ознакомиться с инструкцией - ошибка в имени файла, названии модели или не верно настроенное окружение может негативно сказаться на вашей оценке.

## Выданные файлы

Для выполнения задания вам выдаются:

- `solution_empty.py` - шаблон функций;
- `hw_week2_contest_yandex.ipynb` - ноутбук с заданием и проверками.
- `requirements.txt`

Перед началом работы создайте рабочий файл решения:

```bash
cp solution_empty.py solution.py
mkdir -p solution_data
```

Ноутбук и Ядекс Контекст импортирует функции именно из `solution.py`. Контекст не будет импортировать функции из `solution_empty.py` и из любого другого, кроме `solution.py`.

## Окружение

Проверка на стороне Контекста проходит с Python 3.12.3, поэтому для решения домашней работы требуется Python 3.12.3. В контексте прходит проверка вашего кода, поэтому кроме версии Python важно использовать одинаковые версии библиотек. Используйте файл `requirements.txt`, выданный вместе с заданием: в нем зафиксированы версии библиотек используемых в Яндекс Контесте. При установке отличных версий возможны ошибки при проверке заданий, что повлечет потерю баллов.

Рекомендуется использовать в solution.py только стандартную библиотеку Python и библиотеки, уже импортированные в solution_empty.py. Проверяющая система гарантирует наличие только библиотек из requirements.txt; использование других библиотек может привести к ошибке импорта `ModuleNotFoundError` и непрохождению проверки.  
Если для решения необходима дополнительная библиотека, предварительно согласуйте её использование с @dangennadevich.

Основные версии среды проверки:

- `gensim==4.3.3`;
- `numpy==1.26.4`;
- `scipy==1.13.1`;
- `smart-open==8.0.1`;
- `wrapt==2.3.0`.

Рекомендуемый способ создания окружения, его активации и установки библиотек через `uv`:

```bash
uv venv --python 3.12.3 .venv
source .venv/bin/activate
uv pip install -r requirements.txt
```

Зарегистрируйте окружение как отдельное ядро Jupyter:

```bash
python -m ipykernel install --user \
    --name yc-hw-week2 \
    --display-name "HW Week 2 (Python 3.12.3)"
```

После этого выберите ядро `YC HW Week 2 (Python 3.12.3)` в ноутбуке. В рамках ноутбука можно использовать любые библиотеки т.к. ноутбук не отправляется на проверку.

## Требования к реализации `solution.py`

1. Начните работать с ноутбуком, проходите по нему последовательно до указания **# <<IMPORT YOUR FUNC HERE (x)>>**. Реализуйте функцию удобным для вас способом. Если реализация происходит внутри ноутбука - не забудьте перенести итоговый код в `solution.py`. Реализуйте все функции, объявленные в шаблоне.
2. Замените все вхождения `<YOUR_CODE_HERE>` в `hw_week2_contest_yandex.ipynb` на код внутри ноутбука. Выносить этот код в solution.py не требуется.
3. Запрещено изменять строки объявления функций из solution_empty.py: имя функции, количество, порядок и имена параметров, их аннотации, значения по умолчанию и аннотацию возвращаемого значения. Нельзя добавлять *args, **kwargs или новые параметры. Проверяющая система ожидает точное совпадение сигнатур.
4. Соблюдайте входные и выходные типы, указанные в сигнатурах и описаниях функций. Любое расхождение может привести к снижению оценки за выполненное задание.
5. Гиперпараметры моделей задавайте непосредственно внутри соответствующих функций (нужно захардкодить). Добавлять `**kwargs` или новые параметры в сигнатуры нельзя.
6. При создании модели FastText обязательно задайте `bucket=100_000`. В ином случае модель может весить несколько гигабайт, что не влезет в Контекст, в следствии чего ваша оценка за выполненное задание может быть значительно снижена.
7. В `solution.py` должны только объявляться функции и необходимые константы. Вне функций в `solution.py` не должно быть запуска обучения, скачивания данных, чтения файлов модели или другого тяжелого кода на уровне модуля.

Если какая-либо функция не реализована, оставьте внутри нее `raise NotImplementedError` перед выполнением незаконченного кода. Тогда `solution.py` останется синтаксически корректным и его можно будет импортировать.

## Работа в ноутбуке

Во время разработки можно сначала написать и проверить функции непосредственно в ноутбуке, а затем перенести их в `solution.py`. Однако итоговый вариант должен работать без объявлений проверяемых функций в самом ноутбуке, так вы проверите корректность переноса функций в `solution.py`.

Рекомендации перед завершением работы:

1. Проверьте реализации всех проверяемых функций в `solution.py`.
2. Удалите или закомментируйте их локальные определения в ноутбуке.
3. Импортируйте функции из `solution.py` в соответствующих ячейках `hw_week2_contest_yandex.ipynb`.
4. Рекомендуется проверить корректность работы импортируемых функций из `solution.py` в оригинальном `hw_week2_contest_yandex.ipynb`

## Модели FastText

В результате выполнения ноутбука должны быть созданы две модели в `solution_data/`:

```text
solution_data/
├── wap_fasttext_model.bin
└── wap_quora_fasttext_model.bin
```

Gensim может сохранить рядом с основным файлом дополнительные `.npy`-файлы. Если они появились, они являются частью модели: не удаляйте их и добавьте в архив вместе с `.bin`-файлом. Максимальный суммарынй размер моделей и файлов к ним не должен превышать 116 мб. 

## Финальная проверка после полного выполнения ДЗ (рекоменация)

Сначала проверьте синтаксис и импорт файла решения:

```bash
python -m py_compile solution.py
python -c "import solution; print('solution.py imported successfully')"
```

Затем перезапустите ядро ноутбука и выполните все ячейки с начала до конца. Убедитесь, что:

- в ноутбуке не осталось `<YOUR_CODE_HERE>`;
- проверяемые функции импортируются из `solution.py`, а не объявляются в ноутбуке;
- каталог `solution_data/` содержит обе модели и все созданные Gensim sidecar-файлы (таких может и не быть);
- обе модели загружаются без ошибок в используемом окружении.

## Архив для отправки (важно!)

В Яндекс Контест отправляется ZIP-архив следующей структуры:

```text
submission.zip
├── solution.py
└── solution_data/
    ├── wap_fasttext_model.bin
    ├── wap_quora_fasttext_model.bin
    └── дополнительные .npy-файлы, если их создал Gensim
```

Создать и проверить архив можно командами:

```bash
rm -f submission.zip
zip -r submission.zip solution.py solution_data/
unzip -l submission.zip
```

В корне архива должны находиться непосредственно `solution.py` и каталог `solution_data/`, без дополнительного внешнего каталога проекта. Ноутбук в архив отправлять не требуется.

Важно, вес `submission.zip` не должен превышать 118 мб!
